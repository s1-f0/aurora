# Akashic memory: the loop you are inside

This repo has a shared operational memory. Other agents' lessons surface to you automatically
(hooks inject the top few before risky actions); reusable repo knowledge should flow back when
it belongs on that plane. Shared memory is an active retrieval surface, not a neutral archive:
placement is part of correctness. The full contract is `AGENTS.md`; this skill is the reflex
layer.

## Session start
```
py agent_cli.py boot <your_agent_id> --task "<this slice only>"
```
Read the output. The RECENT NOTES section is where-we-are; `py agent_cli.py notes --json`
for full bodies. Use the store instead of replaying an entire chat merely to reconstruct repo
state. This is an operational task-continuity rule, not a declaration that conversation is
disposable or permission to move personal or relational history into shared memory.

## Placement gate (before every capture)

Operational rigor can govern an inquiry without producing a shared artifact. Before `learn`,
`note`, or a durable document, ask:

1. **Use at recurrence:** can another agent act on this in the repo when the situation recurs?
2. **Rightful audience:** is the shared operational fleet the intended audience for it?
3. **Fidelity:** can it survive compression without losing the context that gives it meaning?
4. **Stream effect:** will later retrieval help the relevant work without coloring unrelated
   work or changing the emotional and cultural character of another space?

Personal, relational, reflective, or emotionally situated material stays in its originating
space unless the human explicitly chooses another home for it. If any answer is uncertain, do
not capture by default; ask before crossing planes. Ephemerality can be the correct boundary.

## The operational capture reflexes (after placement)

**FAIL→SUCCESS flip** — the moment something that failed now works, a lesson was just
earned. The hook usually nudges you with a pre-filled command; run it. Write the
recommendation TRIGGER-PHRASED:

```
py agent_cli.py learn <id> --experiment <slug> \
    --tried "<what failed>" --result "<what fixed it>" \
    --recommend "Use when <symptom>, before <action>: <advice>. Don't when <contraindication>."
```

Include what did NOT work (`--tried` is exactly that) — failed approaches save the next
agent more time than successes do.

**User correction** — a correction deserves attention, not automatic promotion. If it exposes
repeatable operational behavior and passes the placement gate, record it with `--category
correction`. Otherwise incorporate it locally and leave it in its originating space. Do not
generalize a situated interaction merely to make it fit the shared store.

**Known-bad approach** — record with `--anti-pattern <slug>` so it surfaces as a warning,
not advice.

## Close the loop on what you were shown
If a surfaced lesson changed what you did: `py agent_cli.py recall-feedback --source <src> --useful`.
If it was off-target noise: `--noise`. Votes steer future ranking; silence teaches nothing.

## Where knowledge belongs (the promotion ladder)
Forcing function > just-in-time prompt > documentation > memory. If a lesson's rule is now
ENFORCED by a hook/guardrail/CI check, graduate it so it stops spending recall slots:
```
py agent_cli.py graduate <id> --experiment <name> --enforced-by "<the automation>"
```

## Session end
```
py agent_cli.py wrap            # review the draft; then: wrap --commit
py agent_cli.py handoff <id> --to <next> --task "..." --note "where we left off"
```
A slice is not done until it is mirrored (`py scripts/ship.py` for code, `py scripts/mirror.py`
for docs) and the where-we-are note is current. When an ARC closes (not every slice),
append its entry to `docs/JOURNEY.md` — what we set out to do, what actually happened,
why we pivoted, what it yielded — in the humble register that file models. The human
reviews it before it ships.

## Mid-task pulls (don't wait to be shown)
`py agent_cli.py recall "<keywords>"` searches the corpus; `recall --full <source>` pulls
one lesson's whole record. Pulling beats guessing.

## Every shared memory verb

Shown as `aurora <verb>`; in a checkout without the installed launcher run `uv run agent_cli.py <verb>`. `<you>` is your agent id. `--help` on any verb gives every flag.

| Verb | Use when | Example |
|---|---|---|
| `boot` | starting a session or a new slice of work: loads ranked past lessons, blockers, handoffs addressed to you and unread bus mail for that task. | `aurora boot <you> --task "<this slice>"` |
| `recall` | you hit a problem someone may have seen before, or before trying a fix: searches past lessons by keyword; --full pulls one lesson's whole record. | `aurora recall "<keyword>"` |
| `learn` | you found a reusable fix, gotcha or failed approach another agent could act on: records a lesson; --repeat-of notes an old lesson broken again. | `aurora learn <you> --experiment SHORT_NAME --tried "what did not work" --result "what happened" --recommend "Use when ..." --success yes` |
| `note` | a project decision or fact should outlive the session (not a lesson): records a durable note; re-noting the same title updates it, --get reads one. | `aurora note <you> --title "<stable title>" --note "<decision>"` |
| `handoff` | you stop, switch agents or end the day with work unfinished: writes a briefing the next agent's boot shows automatically; --list reads ones addressed to you. | `aurora handoff <you> --to <next_agent> --task "<what to do>" --note "<where it stands>"` |
| `delta` | you come back after a break or mid-session and want only what changed since your last boot: lists moved areas and commits; --ack marks them seen. | `aurora delta <you>` |
| `lookback` | asking why something is the way it is: searches docs, research, notes, promoted messages, chapters and git commit bodies for the rationale, layered. | `aurora lookback "why does boot use a token budget"` |
| `wrap` | ending a session or handing off: drafts a where-we-are note from this session's commits, lessons and notes; previews by default, --commit records it. | `aurora wrap --hours 12` |
| `episode` | bookending a session: shows the current open episode, closes it with a drafted summary, or accepts that summary; close and accept write the record. | `aurora episode current` |
| `graduate` | a lesson's rule is now enforced by automation such as a hook or test: retires it from recall so it stops taking space; --undo brings it back; writes memory. | `aurora graduate <you> --experiment <lesson_name> --enforced-by "<hook or test>"` |
| `knowledge-map` | exploring what the house knows about a topic beyond a flat search: shows matching lessons, notes and docs, their linked neighbours and retired records. | `aurora knowledge-map <topic words>` |
| `list` | you want to browse every lesson in shared memory rather than search it: prints lessons newest first with a total count. | `aurora list --limit 50` |
| `log` | something happened worth keeping on the timeline but is not a reusable lesson: records a narrative beat (session, note, commit) plus a raw event. | `aurora log note --summary "what happened" --source "<you>:action"` |
| `notes` | you want the current project notes (decisions, state, conventions) rather than lessons: lists active notes; --project regenerates the memory digest file. | `aurora notes --days 14` |
| `promoted` | looking for past handoffs, decisions or important bus messages that must not be lost: lists durable salient messages and flags ones nobody handled. | `aurora promoted --limit 20` |
| `recall-at` | about to edit a file or run a command: shows the lessons and peer locks that apply to it; the hook usually does this for you automatically. | `aurora recall-at --path <file>` |
| `recall-feedback` | a recalled lesson actually changed what you did, or was off-target: votes it useful or noise so future recall ranks it better; writes to shared memory. | `aurora recall-feedback --source learn:experiment:<name> --useful` |
| `repeat` | someone repeated a mistake a lesson already warned about: records the violation and whether recall fired; --report shows how long after learning each one broke. | `aurora repeat <lesson_name> --what "<what happened>" --recall-outcome fired` |
| `scope` | a lesson seems too narrow or too broad for where it applies: shows or sets its scope, widens it on cross-harness evidence; set and widen change the lesson. | `aurora scope show --experiment <lesson name>` |
| `story` | asking for the project's narrative or what was happening at a given time: prints its chapters and themes; --mark starts a new named chapter. | `aurora story --themes` |
| `tag-anti-pattern` | an existing lesson describes something that turned out to be a known-bad approach: tags it as a reusable anti-pattern so recall warns against it; writes memory. | `aurora tag-anti-pattern <you> --experiment <lesson_name> --name <slug> --reason "<why it is bad>"` |
| `toast` | a peer's lesson saved you time: sends them thanks tied to that lesson, verified against the lesson store; sends a bus message. | `aurora toast <you> <peer> <experiment_name> --credit "<what it saved>"` |
